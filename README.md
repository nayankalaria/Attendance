# Attendance Alerts — Shiper Docker deployment

This package adapts the supplied Flask attendance app for a Shiper Dockerfile deployment and includes your uploaded `students.xlsx`.

## Important: persistent storage must be confirmed

The app stores `students.xlsx`, `attendance_log.csv`, the Playwright WhatsApp browser profile and the pairing QR under `DATA_DIR` (default `/data`). For WhatsApp login and attendance records to survive container replacement/redeployment, `/data` MUST be backed by a persistent volume or equivalent durable storage.

Shiper's public documentation describes Dockerfile deployment, project variables and managed PostgreSQL, but does not currently document a persistent application-volume mount. Do not assume the container's writable filesystem survives redeployments. Before using this for real attendance, confirm with Shiper support whether your plan/project can mount a persistent volume at `/data`. If it cannot, this Playwright session cannot be guaranteed to persist on Shiper cloud; use an external durable storage design or Shiper self-hosted instance instead.

## Included changes

- Chromium runs headless in the cloud.
- WhatsApp QR is captured and displayed inside the authenticated dashboard while pairing.
- Dashboard and APIs require username/password session.
- Session cookies are HttpOnly, Secure and SameSite=Lax.
- App listens on `0.0.0.0:$PORT`.
- One Gunicorn worker is used because the WhatsApp worker queue is in-process.
- Data is stored below `/data`.

## Deploy to Shiper

1. Put this folder in a **private GitHub repository**. The workbook contains parent phone numbers; do not make the repository public.
2. In Shiper, choose **Add Project** and connect the private repository.
3. Select **Dockerfile** deployment. Keep Dockerfile path `Dockerfile` and build context/base path at the repository root.
4. In Project → Variables, add:
   - `APP_USERNAME`: dashboard username
   - `APP_PASSWORD`: long unique password (at least 16 characters)
   - `SECRET_KEY`: random secret of at least 32 bytes
   - `SCHOOL_NAME`: your school name
   - `DATA_DIR`: `/data`
   - `PORT`: `8080` (use Shiper's expected port setting if different)
5. Configure a persistent volume mounted at `/data` **if Shiper confirms this is supported**. If no persistent volume is available, pause before connecting WhatsApp or recording real attendance; redeployments may erase the session and local records.
6. Deploy and open the HTTPS domain generated by Shiper.
7. Sign in using `APP_USERNAME` and `APP_PASSWORD`.
8. Click Connect WhatsApp. Wait for the QR image, then scan it from WhatsApp on your phone: Settings → Linked devices → Link a device.
9. Keep the service running. If the session is lost, reconnect and scan a new QR.

## Local Docker test

```bash
docker build -t attendance-alerts .
docker run --rm -p 8080:8080 \
  -e APP_USERNAME=schooladmin \
  -e APP_PASSWORD='use-a-long-password-here' \
  -e SECRET_KEY='replace-with-a-long-random-secret-value' \
  -e SCHOOL_NAME='Your School' \
  -e COOKIE_SECURE=false \
  -v attendance_data:/data \
  attendance-alerts
```

Open http://localhost:8080.

## WhatsApp and reliability caveats

- This uses the existing Playwright automation against WhatsApp Web, not the official WhatsApp Business API. It is unofficial and may break when WhatsApp changes its web UI.
- Automated messaging may trigger WhatsApp restrictions. Send only appropriate attendance notifications to parents who have agreed to receive them; avoid unsolicited or bulk campaigns.
- The app's `sent` status means the web UI send action completed; it is not a delivery/read receipt from WhatsApp.
- QR image is available only while WhatsApp presents its pairing QR.
- Keep `APP_PASSWORD`, `SECRET_KEY`, parent phone numbers and `wa_profile` private.
- This is a starter deployment, not a security audit or production compliance certification.
